# nachr-stoichiometry

This repository holds the implementation of a bioinformatic pipeline which aims
to rank the most probable pentameric stoichiometries of the nicotinic
acetylcholine reseptors of salmon lice based on modelling with
AlphaFold-Multimer as part of the master's thesis
_Determining the stoichiometry of a nicotinic aceylcholine reseptor (nAChR1) in
salmon lice_. It also includes the sequences and models used for the thesis.


## Dependencies

This pipeline processes the models generated by running AlphaFold-Multimer using
a selection of scoring functions. The pipeline is set up to use the following scoring
functions:

 *  **[AlphaFold2][alphafold2]** is a deep learning based program which predicts
    the 3D structures of proteins directly from the sequence, with
    AlphaFold-Multimer supporting multimer proteins. As part of this modelling,
    each candidate model is scored. This pipeline is designed to work on
    predicted models from AlphaFold-Multimer. The pipeline extracts the
    _pTM+ipTM_ from the `ranking_debug.json` file, which is assumed to be
    located in the same folder as the generated PDB models.

 *  **[PRODIGY][prodigy]** is a scoring function which can evaluate
    interfaces between two or more chains in a PDB model. Available e.g. through
    GitHub and PyPI.

 *  **[GDockScore][gdockscore]** is a scoring function which can
    evaluate the interface between two chains in a PDB-model. GDockScore was
    developed to evaluate decoys from traditional docking. Available on GitLab.
    
 *  **[ZRANK][zrank]** is a scoring function which can evaluate the
    interface between two chains in a PDB-model. ZRANK was developed to evaluate
    decoys from traditional docking. Available for free for academic users
    through special contact form.

 * **[pdb-tools][pdb-tools]** is a set of tools for manipulating PDB-files. The
   pipeline uses three standalone python scripts from pdb-tools:
   `pdb_chainbows.py`, `pdb_selchain.py` and `pdb_tofasta.py`. These are licensed
   under the Apache License 2.0 and copies are included in this repository.

The pipeline is primarily implemented in `bash` using standard tools included on
most GNU/Linux systems with some components writted in Python. The pipeline was
developed on Ubuntu 22.04 LTS and tested on Debian 12.

[alphafold2]: https://github.com/google-deepmind/alphafold
[prodigy]: https://github.com/haddocking/prodigy
[gdockscore]: https://gitlab.com/mcfeemat/gdockscore
[zrank]: https://zlab.wenglab.org/zdock/index.shtml
[pdb-tools]: https://github.com/haddocking/pdb-tools


## Running the pipeline

The pipeline is run from the `process.sh` script in the pipeline directory:

    pipeline/process.sh [-v] PDBDIR OUTDIR

    Where
    PDBDIR is the directory with the PDB-files to be processed.
    OUTDIR is the directory where the processed files should be stored.

To generate the results discussed in the thesis:

    ./pipeline/process.sh -v models/tca-nachr/ processed/tca-nachr/
    ./pipeline/process.sh -v models/lsa-nachr1/ processed/lsa-nachr1/

By default the script assumes that `prodigy` and `zrank` are available in `$PATH`,
but if the environmental variables `PRODIGY` or `ZRANK` exist the pipeline will
instead invoke the command defined there.

To run GDockScore, the GDockScore repository needs to have been cloned locally
and installed in a virual environment with its dependencies. The path to these
are given with the environmental variables `GDOCKSCORE_DIR` and
`GDOCKSCORE_VENV` respectively. These default to folders ~/gdockscore and
~/gdock. To use Conda instead of venv, set the environmental variable
`GDOCKSCORE_CONDA` to the name of the conda environment (`GDOCKSCORE_DIR` is
still needed).


## Adding scoring functions

The pipeline has been designed so that it should be easy to add (or remove)
scoring functions. Aside from extracting the _pTM+ipTM_ scores generated by
AlphaFold2, all scoring functions are implemented as bash libraries in the
`scoring/` folder and called from the `run_scoring_functions` function in
`scoring/scoring.sh`.
